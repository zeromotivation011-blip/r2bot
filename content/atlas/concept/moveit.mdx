**MoveIt** is free, open-source software for [ROS](/atlas/concept/ros2) that moves robot arms. You tell it where the gripper should go; it works out the joint angles, plans a path that avoids obstacles and the arm's own body, and sends the motion to the robot. If [Nav2](/atlas/concept/nav2) is how a ROS 2 robot *drives* somewhere, MoveIt is how a robot arm *reaches* somewhere. The current version, **MoveIt 2**, runs on ROS 2 and is described by its documentation as "the robotic manipulation platform for ROS 2" ([MoveIt 2 docs](https://moveit.picknik.ai/main/index.html)).

## Start here: "pick up that cup"

Asking an arm to pick up a cup sounds like one instruction. It is actually four hard problems:

1. **Where should each joint be?** The gripper's target is a position and orientation in space; the motors only understand joint angles. Converting one into the other is [inverse kinematics](/atlas/concept/inverse-kinematics).
2. **How do I get there without hitting anything?** The table, the cup, a person's hand, and the arm's own links are all in the way. Finding a safe route is [motion planning](/atlas/concept/motion-planning).
3. **Is this pose safe?** Every candidate pose along the way has to be tested for contact with the world and with itself: [collision checking](/atlas/concept/collision-checking).
4. **How fast can each joint move?** A geometric path is not yet a motion. It needs timing that respects each joint's speed and acceleration limits before it can be sent to the motors.

MoveIt bundles all four, so "go here" becomes one request.

## How it works (in brief)

- **It learns your robot from description files.** The physical arm comes from its [URDF](/atlas/concept/urdf); a second file, the SRDF, adds which joints form the "arm" and "gripper" groups and which link pairs do not need collision checking (adjacent, always touching, or never able to collide). The MoveIt Setup Assistant generates this configuration ([Northwestern ROS notes](https://nu-msr.github.io/ros_notes/ros2/moveit.html)).
- **It keeps a model of the world.** The *planning scene* holds the robot's current state plus obstacles (from a depth camera or added by code), and objects attached to the gripper.
- **It plans with swappable planners.** By default MoveIt uses the Open Motion Planning Library (OMPL), a collection of sampling-based planners such as [RRT](/atlas/concept/rrt); the Pilz industrial motion planner and CHOMP are also available out of the box ([MoveIt concepts: Motion Planning](https://moveit.picknik.ai/main/doc/concepts/motion_planning.html)).
- **It solves inverse kinematics with plugins.** The default is KDL, a numerical solver based on the Jacobian ([MoveIt concepts: Kinematics](https://moveit.picknik.ai/main/doc/concepts/kinematics.html)).
- **It executes through controllers.** The central `move_group` node sends the timed trajectory to the robot's controllers over the `FollowJointTrajectory` action ([MoveIt concepts: move_group](https://moveit.picknik.ai/main/doc/concepts/move_group.html)).

The ROS 2 architecture in detail (nodes, plugins, the setup steps and the first demo to run) is on the [MoveIt 2 page](/atlas/concept/moveit2-stack).

## MoveIt vs MoveIt 2

| | MoveIt (MoveIt 1) | MoveIt 2 |
|---|---|---|
| Runs on | ROS 1 | [ROS 2](/atlas/concept/ros2) |
| Source code | [moveit/moveit](https://github.com/moveit/moveit) | moveit2 repository ([ROS Index](https://index.ros.org/r/moveit/)) |
| Use it for | Maintaining existing ROS 1 systems | Any new project |

The ideas (planning groups, planning scene, planners as plugins, `move_group`) carried over from MoveIt 1 to MoveIt 2, so most tutorials on concepts apply to both; commands, launch files and APIs differ. MoveIt 2 packages are released on ROS Index for current ROS 2 distributions such as Humble and Jazzy ([ROS Index](https://index.ros.org/r/moveit/)). Development is led by PickNik Robotics, according to the project's README ([ROS Index](https://index.ros.org/r/moveit/)).

## Where you'll see it

- **[Pick and place](/atlas/concept/pick-and-place)** and bin picking: reach a part, grasp it, carry it around obstacles, set it down.
- **Teaching and research**: university robotics courses use MoveIt to put a simulated or real arm in students' hands without first writing a planner (for example [Northwestern's ROS 2 notes](https://nu-msr.github.io/ros_notes/ros2/moveit.html)).
- **Prototyping industrial cells**: inspection, machine tending and assembly, where an arm has to reach many targets without hitting fixtures.
- **Interactive planning in [RViz](/atlas/concept/rviz2)**: drag the gripper's goal marker, press *Plan*, watch the preview, then *Execute*.

## Why it matters

Writing inverse kinematics, a motion planner, a collision checker and controller integration for one arm is a large, specialist job. MoveIt turns it into configuration: describe your robot, choose your planners, and spend the time on the actual task. That is why it is a common starting point for robot arms in ROS.

## Common questions

### What is MoveIt used for?

Moving robot arms safely. Give MoveIt a goal for the gripper (or a set of joint angles) and it plans a collision-free motion and sends it to the arm. It is used for pick and place, grasping, inspection and research on manipulators running ROS.

### Is MoveIt the same as MoveIt 2?

They are two generations of the same project. MoveIt (MoveIt 1) runs on ROS 1; MoveIt 2 runs on ROS 2 and was first released in 2019. New projects should use MoveIt 2, because ROS 2 is where development continues.

### Does MoveIt work with any robot arm?

It works with any arm that has a URDF description and joint controllers ROS can talk to. You generate a MoveIt configuration for the arm (the SRDF, planner and controller settings) with the MoveIt Setup Assistant, then launch `move_group` with it.
